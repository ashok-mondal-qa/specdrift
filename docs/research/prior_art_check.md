# Prior-art check: OpenAPI drift/coverage for Playwright UI tests, change-based E2E test selection, cross-framework flaky scorer

Method note (applies to every figure below). All data retrieved 12 Oct 2026. npm figures come from the registry search API (`https://registry.npmjs.org/-/v1/search?text=...`), package documents (`https://registry.npmjs.org/<pkg>`) and the downloads API (`https://api.npmjs.org/downloads/point/last-week/<pkg>`). "dl/wk" = last-week downloads from the downloads API. GitHub stars, last-push dates and archive status come from the GitHub REST API (`repos/<owner>/<repo>`). "README read" means the README text in the npm registry or GitHub was read; "description only" means only the one-line description was seen. Weekly downloads of small packages are noisy (mirrors and bots can account for tens to hundreds per week).

## Key question 1: For each idea, is there an actively maintained open-source tool that already does the core job? If yes, how widely used is it and what remains uncovered?

### Takeaway
No idea is fully solved by a widely used open-source tool, but none is empty either. Idea 1 has small, recent packages covering each half separately (coverage: `pw-radar`, `@tracecov/playwright`; mock validation: `openapi-mock-validator`) and nothing found that joins live responses, HAR and `page.route` mocks in one Playwright-native check. Idea 2 is the most open at the "coverage-per-test for Playwright" level, with Playwright itself having declined it. Idea 3 is the most crowded: `ctrf-io/github-test-reporter` (378 stars) already does history-based flaky rate plus PR comments with no hosted service, leaving only scoring, quarantine output and the TestNG/Appium angle.

#### Idea 2: Change-based test selection for Playwright E2E

First-party behaviour:

- Playwright `--only-changed [ref]`: "Only run test files that have been changed between 'HEAD' and 'ref'"; Git only. Release notes for 1.46 add: "This will also run all test files that import any changed files." Application source that a test reaches only through the browser is not considered. — [Playwright CLI docs](https://playwright.dev/docs/test-cli); [Playwright release notes](https://playwright.dev/docs/release-notes)
- Playwright 1.56 "Added `--test-list` and `--test-list-invert` to allow manual specification of specific tests from a file." Playwright 1.62 added a `reporter.preprocess()` hook that "runs after the configuration is resolved and before reporter.onBegin()" and can mark tests skipped or excluded. — [Playwright release notes](https://playwright.dev/docs/release-notes)
- Playwright issue #38096, "Exploration: Detect website changes from PR with ultrathink analysis", opened 1 Nov 2025: a contributor said it "seems like something that can happen entirely outside of Playwright"; maintainer Pavel Feldman replied "Out of scope" and closed it on 11 Dec 2025. — [microsoft/playwright#38096](https://github.com/microsoft/playwright/issues/38096)

## Key question 2: For each idea, what precise, verifiable differentiation would a new project have, if any? If none, say so plainly.

### Takeaway
Idea 1 has a real, checkable gap (validating `page.route` mocks, HAR and live browser responses against a spec, plus UI-level operation coverage, in one free Playwright-native tool). Idea 2 has a real gap in mechanism (measured per-test coverage for Playwright feeding `--test-list`), with a first-party hook now available to build on. Idea 3 has little differentiation left beyond TestNG/Appium quarantine output and scoring on top of CTRF; as a generic "flaky scorer with PR comment" it is not novel.

### Cited Findings

#### Idea 1
- No package found validates `page.route` mock bodies or fixtures automatically: `openapi-mock-validator` requires the consumer to load the spec, match the path and call `validateResponse` per payload. — [npm openapi-mock-validator](https://www.npmjs.com/package/openapi-mock-validator)
- No free package found accepts HAR for spec validation or coverage: TraceCov's HAR import is Professional-only; `pw-radar` documents no HAR input; `har-to-openapi` 3.0.1 (7 Sep 2026, 5,173 dl/wk) converts HAR into a new spec rather than checking against one. — [TraceCov docs](https://docs.tracecov.sh/integration/javascript/); [npm pw-radar](https://www.npmjs.com/package/pw-radar); [npm har-to-openapi](https://www.npmjs.com/package/har-to-openapi)
- Existing coverage tools target API tests: `@tracecov/playwright` instruments the `request` fixture; `pw-radar` wraps `APIRequestContext`, with UI capture left to a user-written listener. — [npm @tracecov/playwright](https://www.npmjs.com/package/@tracecov/playwright); [npm pw-radar](https://www.npmjs.com/package/pw-radar)
- Existing coverage tools do not validate response bodies: `pw-radar` never records response values; TraceCov docs describe coverage and unmatched requests, not conformance errors. — [npm pw-radar](https://www.npmjs.com/package/pw-radar); [TraceCov docs](https://docs.tracecov.sh/integration/javascript/)
- The hosted route to "mocks versus OpenAPI" is PactFlow bi-directional testing, which needs consumer contracts in pact format and a PactFlow account (free Starter limited to 2 integrations). — [PactFlow pricing](https://pactflow.io/pricing); [PactFlow BDCT docs](https://docs.pactflow.io/docs/bi-directional-contract-testing)

#### Idea 2
- Playwright's own selection stops at test files and their imports. — [Playwright release notes, 1.46](https://playwright.dev/docs/release-notes)
- The one coverage-per-test implementation is unmaintained (`tia-js`, last publish 30 Sep 2025, repo 1 star). — [npm tia-js](https://www.npmjs.com/package/tia-js); [GitHub](https://github.com/psturc/tia-js)
- `sniffler` needs a manually written test-to-source manifest. — [GitHub sniffler](https://github.com/callstackincubator/sniffler)
- `jev-playwright` is probabilistic, needs a paid external key and sends diffs and test source to a third party. — [npm jev-playwright](https://www.npmjs.com/package/jev-playwright)
- Datadog's coverage-based product does not list Playwright and works at file level. — [Datadog docs](https://docs.datadoghq.com/tests/test_impact_analysis/setup/javascript/)
- The integration points exist first-party: `--test-list` (1.56) and `reporter.preprocess()` (1.62). — [Playwright release notes](https://playwright.dev/docs/release-notes)

#### Idea 3
- History, flaky rate and PR comment without a server already exist in a 378-star project that accepts JUnit. — [ctrf-io/github-test-reporter](https://github.com/ctrf-io/github-test-reporter)
- That project's page does not mention quarantine, a score or a flaky threshold gate. — [ctrf-io/github-test-reporter](https://github.com/ctrf-io/github-test-reporter)
- Score plus quarantine plus PR comment from JUnit XML already exists as a published but unused package, with quarantine output for Jest, pytest and JUnit only. — [npm @phoenixaihub/flake-finder](https://www.npmjs.com/package/@phoenixaihub/flake-finder)
- Tools that automate quarantine for Playwright are Playwright-only (`playwright-smart-reporter`, `@flakytests/cli`) or hosted (Trunk, Mergify, Captain Cloud). — [npm playwright-smart-reporter](https://www.npmjs.com/package/playwright-smart-reporter); [npm @flakytests/cli](https://www.npmjs.com/package/@flakytests/cli); [Trunk pricing](https://trunk.io/pricing); [Captain OSS guide](https://www.rwx.com/docs/captain/oss/guide)

### Inferences
- Idea 1 defensible claims, each testable against the packages above: (a) reads `page.route`/`route.fulfill` bodies and JSON fixtures and validates them against the spec without per-call code; (b) accepts HAR in the free tool; (c) validates live browser response bodies, not just records them; (d) reports spec-operation coverage for UI tests with a per-test breakdown; (e) MIT-licensed with a public repo, unlike TraceCov's community licence. Claim "first OpenAPI coverage for Playwright" would be false (`pw-radar`, TraceCov); claim "first mock-drift validator" would be false (`openapi-mock-validator`).
- Idea 1 honest positioning: "partly covered; the combination and the UI/mock focus are new", not "novel".
- Idea 2 defensible claims: (a) selection from measured per-test browser coverage rather than import graph, manifest or model; (b) deterministic and offline; (c) emits a native `--test-list` file or uses `preprocess()`; (d) test-level rather than file-level. Claim "first test impact analysis for Playwright" would be false (`tia-playwright`, `sniffler`, `jev-playwright`, Sealights, CloudBees).
- Idea 2 risk worth stating in the report: coverage-based selection for E2E is unsafe for changes that coverage cannot see (backend, config, CSS, data), which is why `jev-playwright` and `impact-gate` both hedge about missed tests. A new tool would need a documented fallback to the full suite.
- Idea 3 defensible claims are thin: (a) one quarantine list emitted in forms TestNG and Playwright can both consume; (b) Appium-aware grouping (device, platform) if built; (c) a score that separates regression from flake on top of CTRF. As a general flaky scorer with PR comment it is not novel, and the most credible form would be a contribution to or thin layer over CTRF tooling rather than a standalone product.

### Gaps
- None of the differentiation claims were tested by installing the competing packages; they rest on README and docs text. A README can omit features.
- Whether `pw-radar`'s English README or later commits add HAR or mock support was not checked beyond the registry README for 0.2.2.
- No evidence was gathered on demand (issues, forum threads) for any of the three ideas beyond download counts.

## Key question 3: Are there any signs first-party tools (Playwright, Redocly, CTRF, GitHub) are about to close the gap?

### Takeaway
Playwright has explicitly declined test impact analysis and shows no OpenAPI or flaky-history work, while adding hooks that make third-party tools easier. Redocly shows no move toward validating captured browser traffic. CTRF is the one first party actively shipping into its gap (flaky and insights commands, releases within the last two days), so Idea 3 is the most exposed.

### Cited Findings
- Playwright closed the test-impact request as "Out of scope" on 11 Dec 2025. — [microsoft/playwright#38096](https://github.com/microsoft/playwright/issues/38096)
- Playwright added enabling primitives instead: `--only-changed` (1.46), `--test-list` / `--test-list-invert` (1.56), `reporter.preprocess()` (1.62). — [Playwright release notes](https://playwright.dev/docs/release-notes)
- Playwright release notes (latest listed version 1.64; first 100,000 characters read, covering the newest releases) contain no mention of OpenAPI, schema validation or HAR validation, and nothing on flaky history or quarantine beyond `failOnFlakyTests`. — [Playwright release notes](https://playwright.dev/docs/release-notes)
- A search of `microsoft/playwright` issues for "openapi" returned no request for OpenAPI validation or coverage; the nearest results were #42154 "Generics for APIRequestContext and APIResponse" (closed, Aug 2026) and #32986 "typesafe / generic matchers" (closed, Oct 2024). A search for "quarantine flaky" returned nothing. — [issue search: openapi](https://github.com/microsoft/playwright/issues?q=openapi); [issue search: quarantine flaky](https://github.com/microsoft/playwright/issues?q=quarantine+flaky)
- Redocly Respect remains request-sending: a server must be running because Respect "sends real HTTP requests"; no HAR, proxy or Playwright input is documented. — [Respect docs](https://redocly.com/docs/respect)
- Optic, the tool that did verify captured test traffic against OpenAPI, is archived after the Atlassian acquisition. — [GitHub opticdev/optic](https://github.com/opticdev/optic)
- CTRF is shipping fast in this area: `ctrf-cli` 0.5.0 (10 Oct 2026) has `flaky` and `add-insights`; `github-test-reporter` v1.3.2 (11 Oct 2026) has flaky-rate, insights and previous-results reports; most `ctrf-io` reporters were republished on 10–11 Oct 2026. — [npm ctrf-cli](https://www.npmjs.com/package/ctrf-cli); [GitHub ctrf-io/github-test-reporter](https://github.com/ctrf-io/github-test-reporter)
- MSW's first-party Playwright binding `@msw/playwright` 0.7.0 (28 Sep 2026) is growing (226,195 dl/wk), and `@mswjs/source` generates handlers from OpenAPI and HAR; neither README read describes validating handlers against a spec. — [npm @msw/playwright](https://www.npmjs.com/package/@msw/playwright); [npm @mswjs/source](https://www.npmjs.com/package/@mswjs/source)

### Inferences
- Idea 2 is the safest from first-party encroachment: the maintainer response puts it outside Playwright's scope, and the new hooks lower the build cost.
- Idea 1 has no visible first-party threat from Playwright or Redocly. The more likely competitors are TraceCov (weekly releases, could add a browser/`page` integration and already has HAR import behind a paid tier) and the MSW ecosystem, where mocks generated from the spec reduce drift at source.
- Idea 3 is the most likely to be closed by a first party: CTRF already has history, flaky rate and PR comments, and quarantine or threshold gating would be a small step. This is a judgement from release cadence, not from a published roadmap.

### Gaps
- No public roadmap was found or read for Playwright, Redocly, CTRF or TraceCov; the conclusions rest on release notes, READMEs and one closed issue.
- GitHub's own roadmap for native test reporting or flaky detection in Actions was not checked.
- The CTRF organisation's discussions and open issues were not searched for quarantine or scoring proposals.
- The older half of the Playwright release notes page was not read; it covers earlier versions and is unlikely to change the picture.
